WHAT SWIFT IS
When a flood threatens a neighborhood, an AI agent phones every household in order of predicted water arrival
(Retell does phone + voice; our server decides every reply using Qwen3-VL on the organizers' GB10 model server).
It records who needs help / can help (truck, boat, seats) / is safe / never answered (-> door-knock list).
A deck.gl dashboard replays Hurricane Harvey in Bear Creek (west Houston) and makes one LIVE call to Eric's phone.

NEXT TASK: build the Render relay (Eric chose this)
  Retell --wss--> Render relay (public) <--wss (outbound from laptop)-- relay client on laptop --> localhost:8080
- relay/app.py (deploy on Render, free web service):
    * WS  /agent                     — the laptop's single persistent connection (protect with a shared secret,
                                        e.g. env RELAY_SECRET as ?token=; reject others).
    * WS  /llm-websocket/{call_id}   — Retell connects here; relay forwards frames tagged with call_id over /agent
                                        ({"type":"open"|"msg"|"close","call_id",...}) and routes replies back.
    * POST /retell/webhook           — forward body over /agent as {"type":"webhook","body":...}; return 200.
    * GET /health                    — for Render + keep-warm.
- relay/client.py (runs on laptop): connect wss://<app>.onrender.com/agent?token=..., auto-reconnect with backoff,
  ping every ~20 s (keeps free tier awake); per call_id open a local ws://localhost:8080/llm-websocket/{call_id}
  and pipe both ways; POST webhooks to http://localhost:8080/retell/webhook. Server code stays unchanged.
- render.yaml (rootDir relay/ or startCommand "uvicorn relay.app:app --host 0.0.0.0 --port $PORT"), small
  requirements (fastapi, uvicorn[standard], websockets/httpx).
